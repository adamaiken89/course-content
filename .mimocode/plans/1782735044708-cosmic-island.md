# Plan: Store Independence Rule + Hook Coordination Layer

## Verdict: Fits Naturally

This project is Zustand course content (markdown lessons + quizzes). The new rule — "stores must not depend on other stores" — aligns with the existing atomic stores philosophy (M14) and extends it. It fits as a refinement of existing modules, not a new module.

---

## Current Problem in Module Content

**Module 05** teaches cross-store reads via `.getState()`:
```typescript
// cartStore reads auth token
const token = useAuthStore.getState().token
```

**Module 08** teaches cross-slice action calls:
```typescript
// authSlice calls cartSlice
get().clearCart()
```

Both patterns create store-to-store coupling. The new rule eliminates these.

---

## Proposed Architecture

### Rule: Stores Are Islands

Each store is a closed island. Zero imports of other stores. Zero `.getState()` calls to other stores. Store only knows its own state and actions.

### Hook Layer: The Bridge

Custom hooks sit between stores and components. Hooks read from multiple stores, coordinate multi-store actions, and handle side effects. This is the "service layer."

```
Component → useCheckout() hook → useAuthStore + useCartStore + useOrderStore
                                       ↓              ↓              ↓
                                   [island]        [island]      [island]
```

### Atomicity Preservation

Individual store actions remain atomic (single `set` call). Multi-store operations are "eventually atomic" from UI perspective — hook orchestrates the sequence, component sees one logical action.

## Consistency Model

**UI Atomicity** (what user sees):
- Hook calls N store actions sequentially
- React batches state updates in same event handler → all updates flush together
- Component re-renders once with all stores updated

**Data Consistency** (what happens internally):
- If action 3 of 5 fails → first 2 already applied, no automatic rollback
- Hooks handle rollback explicitly in try/catch:

```typescript
function useCheckout() {
  const checkout = useCartStore((s) => s.checkout)
  const clearCart = useCartStore((s) => s.clearCart)
  const addOrder = useOrderStore((s) => s.addOrder)

  return useCallback(async (token: string) => {
    const order = await checkout(token)  // may throw
    try {
      addOrder(order)
      clearCart()
    } catch {
      // rollback: re-add items to cart
      // explicit, not automatic
    }
  }, [checkout, clearCart, addOrder])
}
```

**No magic** — hooks are explicit orchestration. Developer sees the full flow.
